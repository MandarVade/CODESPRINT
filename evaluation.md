# Evaluation & Scoring System

## CodeSprint 2026

Each problem will be evaluated using an automated offline judge.

---

## Test Case-Based Evaluation

* Every problem contains **10 test cases**.
* Your submitted solution will be compiled and executed against all 10 test cases.
* For each passing test case: **+1 point**.
* Total per-question score: **10 points**.
* Total competition score: **100 points**.

---

## Evaluation Criteria

| Criteria                                    |   Weight |
| ------------------------------------------- | -------: |
| Correct output for automated test cases     |     100% |
| Code must compile without errors            | Required |
| Required class and method names must match  | Required |
| No unnecessary output or debugging messages | Required |

---

## ⚠️ Important Notes

* No partial marks are given for a test case. Each test case is either **pass or fail**.
* Wrong answers, compilation errors, runtime errors, or timeouts receive **0 points** for that test case.
* Test cases include normal cases, edge cases, and boundary cases.
* The expected output is compared with the output produced by the submitted solution.
* Students must follow the method signature given in the problem statement.
* Students should not modify the test files or evaluation files.
* The evaluator runs locally and does not require an internet connection.

---

## Java Evaluation

For Java problems:

* The student's `.java` file is compiled by the evaluator.
* The required class and method are loaded and executed automatically.
* Each problem has a separate test file containing 10 test cases.
* The evaluator reports the score as **x/10** and **x/100**.

---

## SQL Evaluation

For SQL problems:

* The SQL query will be executed against the provided database tables and data.
* The result produced by the query will be compared with the expected result.
* Column values and required output must match the problem requirements.
* Incorrect queries, syntax errors, or incorrect result sets receive **0 points** for that test case.
* SQL problems may include different data conditions and edge cases.
* Students should submit only the required SQL query unless the problem specifically asks for additional SQL statements.

---

## Final Ranking

Participants are ranked based on:

1. Total marks out of **100**.
2. In case of a tie, the participant with the **earlier submission time** is ranked higher.
3. If still tied, the participant with more **perfect problems (10/10)** is ranked higher.

All results generated by the automated judge are final.
